01The problem

People and AI agents sign transactions they cannot read. A wallet shows an address, a function name and hex; the signature behind "enable trading" is an unlimited allowance to a look-alike address. An agent's key signs whatever the model decides, and a prompt injection or a wrong merchant ends in a valid signature on the wrong transaction. On Monad a block is final in under a second, so the check has to come before the signature.

02The solution

Baret is a pre-sign check that wallets, dapps and agents call before they sign: one POST /v1/analyze or the @baret/guard SDK. It simulates the transaction on Monad, runs nine detectors, applies the signer's own 25-rule policy and answers Safe, Caution or Blocked, with reasons. It fails closed. For agents: a PaymentGuard vault with on-chain caps per merchant, payment, hour and day, an owner's kill switch, and a Qwen reviewer that can only veto.

03How it works

  • Simulate on Monad with debug_traceCall: every balance change, allowance and contract touched.
  • Detect with nine detectors, including the on-chain reputation registry, Cleanverse identity and Nansen labels.
  • Decide with the signer's own policy.
  • Explain in plain words (KIMI); the model never decides.
  • Missing data means Blocked.

CleanverseA-Pass credentials checked before aUSDC moves; enforced in CompliantPaymentGuard.
EnvioHyperIndex indexes every vault, payment and registry change.
NansenProfiler trust level for the counterparty, as a detector input.
MeraThe web wallet's account layer: one passkey, no seed phrase.
DynamicThe demo agent is a Dynamic server wallet paying from a vault.
AlchemyBatched chain reads for every analysis through its Monad RPC.
KIMIExplains each verdict in plain words; cannot change it.
Qwen 3.8 MaxReviews agent payments with read-only tools; can only veto.
